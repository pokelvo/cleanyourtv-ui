# Status: first applied 2026-10-19, applied again after a factory reset, in daily use since; re-checked
# 2026-10-26 with `pm list packages -d` (this list plus the factory-disabled packages below).

# Same board and firmware as examples/philips-50pus8517, philips-55oled707, philips-65oled706 and
# philips-65oled907: their DO NOT DISABLE notes apply here as written. This is a separate, tailored list
# for the 55" unit: it disables more of the NetTV web apps, the free ad-supported channels, Alexa and the
# launcher customizer, and puts the streaming apps in their own commented section (see below).
#
# Apply:   TV_HOST=<TV_IP> tools/disable.sh examples/philips-55oled907/debloat.txt
# Undo:    TV_HOST=<TV_IP> tools/restore.sh examples/philips-55oled907/debloat.txt com.google.android.tvlauncher
# Everything is DISABLED, not uninstalled. Comment out any line you want to keep.
#
# Stock launcher: com.google.android.tvlauncher is NOT listed: launcher/build-and-install.sh does the Home
#                 handover itself, and restore.sh takes it as the stock launcher to bring back.
# Live TV app:    org.droidtv.playtv (antenna).
#
# Out of the box, org.droidtv.freeviewplayers, 15 uk.co.freeview.* apps and io.mimi.tvapp were already
# disabled on this unit; they are not listed, so restore leaves them as they were.
#
# DO NOT DISABLE on this Philips (all checked on this unit or on the same board):
#   org.droidtv.eum               the SOURCES key: GlobalKey opens org.droidtv.channels/.sources.SourcesDrawerActivity,
#                                 which crashes binding eum's eUMService when eum is disabled
#   org.droidtv.philipstvdrawer   the OPTIONS key: GlobalKey starts the PhilipsDrawer intent, which only this app answers
#   org.droidtv.xtv               the TV core: sources drawer, inputs, the JointSPACE API (ports 1925/1926)
#   org.droidtv.xtvsystem         the TV's system services that xtv depends on
#   org.droidtv.homeintentresolver  decides where the Home key goes; without it Home can stop working
#   org.droidtv.channels          channels and the Sources drawer
#   org.droidtv.playtv            the antenna / live TV app
#   org.droidtv.ambiair, org.droidtv.ambihuecommon, org.droidtv.alhuewizard, org.droidtv.sunrise
#                                 Ambilight, Ambilight + Hue (bridge link and the Hue on/off service) and the sunrise alarm
#   org.droidtv.oad, com.easy.oad firmware updates (over the air and from USB)
#   Also kept: org.droidtv.aurora (xtv retries it forever when it is off; hide it in the launcher instead),
#   org.droidtv.nettvregistration, lkb, icp, contentexplorer, the Vewd browser engine, DTS Play-Fi
#   (com.phorus.playfi.*), org.droidtv.audiocalibration, com.google.android.katniss (Google Assistant),
#   com.google.android.apps.mediashell (Chromecast) and com.google.android.tungsten.setupwraith (can own the
#   saved Wi-Fi network on a wireless set; tools/disable.sh checks it anyway).
#
# Philips quirks seen on this unit:
#   * The screensaver ships off, and tptvservice puts its delay back to "never" at every boot. On an OLED, set
#     it again after each boot (a launcher can do it at boot, as this unit's does).
#   * Ambilight + Hue: when "Ambilight+hue" is enabled in the TV's Ambilight settings, the TV turns the Hue
#     lamps back on at every power-on, whatever was chosen before standby.
#   * The JointSPACE API (port 1926) works from another computer, but called from an app on the TV itself it
#     drives org.droidtv.xtv to 100 % CPU with connections that never close, until the TV is restarted.
#   * SOURCES and OPTIONS reach an accessibility key filter as keycode 602 (scan 757 and 641) before GlobalKey.
#   * usagelogger and demome hold TV_INPUT_HARDWARE, so tools/disable.sh skips them; they are left commented.
